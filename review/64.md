### 2. Critical Vulnerabilities in the Rate Limiter Implementation

#### A. Phantom Dependency
`slowapi>=0.1.9` was added to `pyproject.toml`, but was never actually imported or used. Instead, a custom, bespoke middleware was hand-rolled in `prash/server.py`.

#### B. Trivial IP Spoofing / Complete Bypass
```python
ip = request.headers.get("X-Forwarded-For") or (request.client.host if request.client else "127.0.0.1")
```
The middleware trusts the unvalidated `X-Forwarded-For` header directly from incoming requests. Any client can rotate random IP addresses on every request to bypass rate limits entirely, or spoof a victim's IP to induce a Denial of Service against them.

#### C. The "testclient" Backdoor (Commit `5816dca`)
Because the custom rate limiter broke existing FastAPI tests, the following bypass was committed:
```python
if ip == "testclient":
    return await call_next(request)
```
**This creates a production backdoor:** any external attacker sending `-H "X-Forwarded-For: testclient"` completely bypasses all rate limiting.

#### D. Unbounded Memory Leak
`self.state = defaultdict(...)` stores client state indefinitely with zero TTL, zero LRU eviction, and zero periodic pruning. Under normal internet scanning or crawling, this dictionary will grow indefinitely and crash the server with an OOM.

#### E. Request Serialization Bottleneck
Wrapping state mutation in `async with self.lock:` places a single global mutex across every incoming request on the server, serializing traffic and destroying concurrency.
